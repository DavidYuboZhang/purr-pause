### 原生证据与限制

最终采样：qwindows.dll +0x7e108 → UIAutomationCore.dll（含 +0x128da 等帧）→ combase.dll → rpcrt4.dll/RpcRaiseException → KernelBase.dll/RaiseException。使用本地模块/导出符号，无 PDB 下载；模块及偏移是主要证据，某些最近导出符号带大偏移，不作为准确私有函数名。最初采样的遍历器分别在首帧、重复 PC 处提前停止；保留原输出，修正临时遍历器后才取得最终栈。该诊断器修正不是产品修复。

异常继续使用 [Windows 调试 API 的 NOT_HANDLED 状态](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-continuedebugevent)，没有将它标为已处理或注入异常处理回调；未捕获到第二次机会且退出 0，支持被测程序随后自行处理。首次机会是一次原生异常通知，不等同于进程已崩溃。

输出机制与 [CPython 3.11.18 faulthandler 实现](https://github.com/python/cpython/blob/v3.11.18/Modules/faulthandler.c#L358-L417)、[pytest 默认启用说明](https://docs.pytest.org/en/stable/how-to/failures.html#fault-handler) 一致；原生路径与 [Qt 6.12.0 WM_GETOBJECT 实现](https://github.com/qt/qtbase/blob/v6.12.0/src/plugins/platforms/windows/uiautomation/qwindowsuiaaccessibility.cpp#L33-L50) 一致。此处是本机受控实验支持的分类，不认定为任何特定外部应用在旧轮次触发，不以禁用可访问性或隐藏诊断作为修复。
